# EXP-H2-SOFTARGMIN-SCALE — can the matching path learn once the soft-argmin is not saturated?

**Status of this file:** sections 1–3 were written *before* the training run
finished, from the pre-registered design and the numerical pre-check. Sections 4
onward are filled from the completed run. Nothing in 1–3 was edited afterwards.

**Claim tags:** `MEASURED` (a number produced here, with its protocol),
`DERIVED` (arithmetic on measured numbers), `OBSERVED VISUALLY` (read off a named
image), `INFERRED` (a reading the evidence does not force), `UNKNOWN`.

Phase 1 is untouched (`phase-1-frozen` = `b4207e5`; a test asserts the diff is
empty). The H1 records and checkpoints are untouched: this experiment writes only
`EXP-H2-SOFTARGMIN-SCALE*` paths.

---

## 1. Hypothesis, control, changed variable

**Hypothesis.** The matching pathway of this architecture is untrainable because
the soft-argmin is numerically saturated, not because correspondence is
impossible to learn here. Standardising the aggregated cost before the
soft-argmin — changing nothing else — should restore gradient flow to the feature
extractor and aggregation.

**Control.** `EXP-H1-WORKING-v2`, already trained, **not retrained**.
`cost_volume_shift="left"`, 200 epochs, seed 0, 160 training scenes.

**Changed variable, exactly one.** The regression stage:
`src/models/stereonet/regression.DisparityRegression` (frozen, untouched) is
replaced at construction time by
`phase2/models/scaled_regression.StandardisedDisparityRegression`, which applies

    C_scaled[d,y,x] = (C[d,y,x] − mean_d C[:,y,x]) / (std_d C[:,y,x] + 1e-5)

to the upsampled cost immediately before the frozen `soft_argmin` (imported, not
reimplemented). Per pixel, across the 12 disparity candidates only — never across
the batch, never across space, never using ground truth. Population standard
deviation. No learnable temperature, no annealing, no clipping, no constant
divisor, no new parameter: `MEASURED` — parameter count 423,586, identical to the
control, and the swap leaves every weight tensor bit-identical (test
`test_swap_changes_only_the_regression_stage`).

**Held fixed** by importing the H1 recipe rather than restating it (test
`test_recipe_constants_match_the_control_run` asserts the imports are the same
objects): dataset, split, crop size and sampling, augmentation, seed, optimizer,
learning rate, schedule, batch size, epochs, loss, maximum disparity, precision,
validation protocol, and `cost_volume_shift="left"`.

**Two consequences of the changed variable, recorded before training, not
discovered after:**

1. `MEASURED` — standardisation removes scale, so it also caps peak confidence.
   With one clear winner among 12 candidates the winner receives ≈0.77 of the
   softmax weight regardless of its margin, and the regressed index is pulled
   toward the candidate mean (test
   `test_a_preferred_candidate_wins_but_confidence_is_capped`).
2. `MEASURED` — the fixed `eps = 1e-5` is a floor: scale invariance holds while
   the per-pixel standard deviation is far above it and fails below it, where the
   output collapses toward the uniform mean of 5.5 (test
   `test_scale_invariance_holds_above_the_epsilon_floor_and_fails_below_it`). The
   run records the observed cost standard deviation so the margin can be checked.

## 2. Numerical pre-check (gate, run before training)

`phase2/results/h2_precheck/precheck.json`, regenerated by
`python phase2/scripts/exp_h2_precheck.py --batches 40`.

Protocol: **the control's own weights** (`EXP-H1-WORKING-v2`, sha256
`a5c16c6b…`), the same 40 crops of 256×512 from `hailo_calib` and the same four
`hailo_val` frames for both arms; forward + backward, no optimizer step, nothing
saved. The only difference between the arms is the standardisation.

Stated limitation: this measures what the operator does to a network trained
*without* it. It is a diagnostic of the operator, not a prediction about a
trained H2 model.

`MEASURED` (crop set, means over 40 batches):

| quantity | CONTROL | H2 (scaled) |
|---|---:|---:|
| mean softmax entropy (max 2.4849 nats) | 0.0000 | **2.0889** |
| mean max softmax weight | 1.000000 | **0.253443** |
| fraction of pixels with top-2 gap < 88 | 0.0000 | **1.0000** |
| median top-2 gap | 7.747e+16 | **0.1736** |
| `disparity_initial` std (mean over batches) | 3.7126 | 1.8766 |
| **batches where the matching path receives gradient** | **0.025 (1/40)** | **1.000 (40/40)** |
| batches where the softmax input receives gradient | 0.025 | 1.000 |
| median pixels with gradient into the softmax input | 0 | 105,925 of 131,072 |
| median matching-path gradient norm | 0 | 0.125 |
| median total gradient norm | 60.3 | 71.11 |

`MEASURED` — the gradient reaching the *raw* (pre-standardisation) cost has norm
≈1.3e-19 in the H2 arm: non-zero at 95,747 pixels but far below the 1e-12
presence threshold, because standardisation divides by a ≈1e16 standard
deviation. `DERIVED` — the meaningful tensor is the one the softmax consumes; the
raw-cost gradient being tiny is arithmetic, not gradient starvation, and the
parameter gradients (which also carry `d cost / d parameter`) are healthy.

**Gate decision:** `DERIVED` — the scaling materially desaturates the soft-argmin
(entropy 0.0000 → 2.0889 of a possible 2.4849; max weight 1.000 → 0.253) and
raises matching-path gradient reachability from 1/40 to 40/40 batches. Gate
passed; training authorised.

**Threshold definitions, fixed before the run:** a gradient counts as present
when its norm exceeds **1e-12** (fp32's smallest normal is ~1.2e-38, so this is
far above the noise floor and far below anything that can move an Adam step);
exact zeros are counted separately. A pixel counts as saturated when its top-2
cost gap exceeds **88**, the point where fp32 `exp()` underflows to exactly zero.

## 3. Training configuration

`python phase2/scripts/exp_h2_softargmin_scale.py` — 200 epochs, batch 2, Adam
lr 1e-3 with cosine annealing, seed 0, `hailo_calib` (160 scenes) train,
random 256×512 crops with per-image gain jitter σ=0.1, masked smooth-L1,
fp32, RTX 4060. Validation every 5 epochs on the first 10 `hailo_val` scenes,
full 368×1232 frames, pooled over `gt > 0` — the recorded H1-v2 protocol,
imported from the H1 script rather than restated.

Per batch the run records the total gradient norm and the norms reaching the
feature extractor, aggregation and refinement separately; every 20th batch it
also records softmax entropy, top-2 gap, exact ties, and the gradient reaching
the tensor the softmax consumes.

## 6. Gradient distribution and the tie-driven spikes

`MEASURED` — total gradient norm over all 16,000 batches: median 20.08, p90 51.3,
p95 65.0, p99 93.3, **max 308.0**, no non-finite values, and **zero** batches
above 1e4 (or 1e6, 1e8, 1e10). Control, recorded: median 37.25, **max 3.567e13**.

`MEASURED` (`phase2/results/h2_mechanism/tie_check.json`, 150 identical crops per
arm, at convergence): gradient entered the cost tensor on 5/150 crops for WORKING
— each time at exactly 1 pixel of 131,072 carrying an exact tie, with norms
1.2e7 – 4.0e12 — and on **0/150** crops for H2, which had **no spikes at all**
(max total norm 70.3, matching-path max 17.6, matching-path gradient present on
150/150).

`DERIVED` — the tie-gated spike mechanism identified in the H1 investigation is
absent from H2 in this sample. `INFERRED` — with the softmax no longer saturated,
a tie is no longer a singular event: neighbouring candidates already carry
comparable weight, so a tie contributes an ordinary derivative instead of the only
non-zero one. **Not established:** that the standardisation *causes* the absence
of spikes; the association is 0/150 vs 5/150 in one run per arm, and no
intervention isolating ties was performed.

## 10. Does refinement still dominate?

`MEASURED` — the refinement residual still accounts for 0.867 of the final map's
summed magnitude in H2 (control 0.914), and correlates with the final map at
+0.9999.

`DERIVED`, and stated because the number invites a wrong reading: that share is
unit-confounded. `disparity_initial` is in *candidates* (H2's range 1.34–8.28)
while the final map is in *pixels*; one candidate is 16 px. H2's mean initial map
is ~52 px-equivalent against a mean final disparity of ~25 px, so refinement is now
largely *subtracting*, not supplying, magnitude. The intervention in §8 is the
non-confounded measurement: removing the matching content costs 71.5 D1 points.

`INFERRED` — refinement is still doing substantial work, but it is no longer the
only source of usable signal: in the control it was, and in H2 it is not.

## 11. Anomalies and limitations

1. `MEASURED` — the machine suspended mid-run: no epoch completed between 10:31:35
   and 12:58:48 UTC (2 h 27 min), then training resumed normally. The recorded
   `wall_clock_s` of 12,517 s is therefore inflated and **not** comparable to the
   control's 3,627 s. From per-epoch timestamps the actual rate was 14–19 s/epoch,
   i.e. roughly 3,300–3,800 s of compute. Optimizer state, RNG stream and epoch
   counter were preserved by the suspend; nothing was restarted.
2. `MEASURED` — the experiment record does not carry a top-level
   `cost_volume_shift` key (it is stated inside `held_fixed`). The record is
   immutable, so an additive `NOTE.md` was added beside it and both loaders were
   made tolerant of the absence. A future H2-family script should write the key.
3. Two tooling defects were found and fixed *during* analysis, both of which would
   have produced wrong statements: `stage_stats` measured softmax saturation on
   the raw aggregated cost rather than on the tensor the softmax consumes (wrong
   for any rescaling arm), and `cross_shift` rebuilt models without their
   regression stage. Both were corrected and the affected outputs regenerated; the
   H1 evidence directory was not overwritten (H2 comparisons live in
   `phase2/results/h2_mechanism/`).
4. One seed, 160 training scenes, 40 validation scenes. No significance test was
   run and none is claimed. Nothing here says how this configuration behaves at
   full data scale.
5. The comparison is against `EXP-H1-WORKING-v2` only. `EXP-H1-BASE-v2` was not
   retrained under the scaling, so this experiment does not say what the
   degenerate cost volume would do with a working soft-argmin — that is exactly
   the next experiment.
6. `MEASURED` — the standardisation caps peak softmax confidence at ~0.77 for a
   lone winner among 12 candidates, and H2's observed max weight is 0.43–0.60.
   `INFERRED` — this bounds attainable sub-pixel sharpness; whether it costs
   accuracy is untested.

## 12. Answers to the twelve questions

1. **Did scaling desaturate the soft-argmin?** `MEASURED` yes: entropy 0.0000 →
   1.67–1.83 nats (max 2.485), max weight 1.0000 → 0.43–0.50, median top-2 gap
   ~1e16 → ~0.8, 100 % of pixels below the saturation threshold, at every epoch.
2. **Did gradient reach the matching path?** `MEASURED` yes, on every batch.
3. **On what fraction of batches?** `MEASURED` 16,000/16,000 = 100.00 %; exactly
   zero on none. Control: 3.3 % of sampled crops at convergence.
4. **What happened to gradient magnitude?** `MEASURED` it became ordinary and
   stable: total norm median 20.1, max 308.0 (control max 3.567e13); matching-path
   median 6.85, max 306.7; no non-finite values.
5. **Did spikes remain?** `MEASURED` no: zero batches above 1e4 out of 16,000, and
   0/150 spiking crops at convergence against the control's 5/150.
6. **Were exact ties still responsible?** `MEASURED` ties still occur (14 in 800
   sampled batches, at most 1 per batch) but no longer coincide with spikes,
   because there were no spikes. `INFERRED` mechanism in §6; causality not
   established.
7. **Did `disparity_initial` become spatially meaningful?** `MEASURED` yes:
   correlation with ground truth +0.978 … +0.988 versus −0.001 … +0.283.
   `OBSERVED VISUALLY` road, poles and façades are visible in it.
8. **More correlated with GT?** `MEASURED` yes, as above; and the trained features
   themselves became more matchable (hand-made cost volume +0.414 vs +0.215).
9. **Did EPE/D1 improve?** `MEASURED` yes, secondary: late-window EPE
   4.199 ± 0.090 vs 14.414 ± 0.216, D1 24.78 ± 1.02 vs 80.76 ± 0.38, on the
   recorded protocol, with identical parameter count. One seed; no significance
   claimed.
10. **Does refinement still dominate?** `MEASURED` it still carries most of the
    map's magnitude (0.867), but `DERIVED` that share is unit-confounded, and the
    intervention shows the answer now depends on the matching output (+71.5 D1 when
    it is destroyed, against +0.30 for the control).
11. **Is there evidence of genuine learned stereo correspondence?** `MEASURED`
    yes, on three independent tests: destroying the matching map costs 71.5 D1
    points; corrupting the right image costs 81–84 D1 points in every variant;
    switching the disparity shift off costs 81.8 points. For the control the same
    three tests cost 0.30, at most 0.8, and 0.75 points. `DERIVED` — this is the
    first configuration in this project whose output demonstrably depends on the
    second camera.
12. **Next experiment?** §13.

## 13. Decision

    H2 STATUS: MECHANISTICALLY SUCCESSFUL

All five pre-registered criteria are met: (1) the soft-argmin is unsaturated across
100 % of pixels at every measured epoch; (2) gradient reaches the matching path on
100 % of batches; (3) that gradient is not tie-driven — there were no spikes, and
ties are rare and unremarkable; (4) `disparity_initial` develops visible scene
structure; (5) it correlates with ground truth at +0.98, against a control whose
matching output was a constant or noise. Accuracy also improved sharply, which is
not what the verdict rests on.

`DERIVED`, and this is the finding that matters for the project: H1 was answered on
a broken pathway. Its measured 0.64-point D1 difference was a comparison between
two models that both ignored the second camera; the question "what is a working
cost volume worth?" was never actually tested. It still has not been — H2 changed
the read-out, not the volume.

    NEXT EXPERIMENT:
        EXP-H3-SHIFT-UNDER-SCALE -- rerun the H1 contrast with the pathway
        working: identical to EXP-H2-SOFTARGMIN-SCALE in every respect
        (standardised soft-argmin, same recipe, same seed, same split, same
        budget) except cost_volume_shift="none". Control: EXP-H2-SOFTARGMIN-SCALE
        itself. Primary endpoint: validation EPE/D1 under the recorded protocol,
        with the matching-path gradient fraction and the disparity_initial-vs-
        ground-truth correlation recorded alongside as mechanism checks.

Why this one: H2 has shown that the shift matters *at inference* for a model
trained with it (turning it off costs 81.8 D1 points), but that is not the same as
a controlled training comparison, and it is the exact question Phase 2 opened with.
It is one changed variable against an existing control, it needs one training run,
and its result decides whether the correspondence representation needs redesigning
at all.

Stage E stays **closed**. Seed replication is deferred behind H3: replicating a
56-point effect is less informative than establishing whether the cost volume
itself is now worth anything.
